# autopilot はマージまで自動化し、対象は個人リポジトリに限る

pstack のような自律実行を Claude Code で再現するため、grill で合意したあとは PR のマージまで止めずに進める `autopilot` スキルを置いた。pstack の 23 プレイブックとモデル別の振り分けは移植せず、確証がないときの `advisor()` とマージ前の PR レビューに置き換えた。

決めたこと:

- 対象は Asuforce/* の個人リポジトリだけ。それ以外のリポジトリでは PR 作成(draft)で止める。マージまで任せると、チームのリポジトリで暴発したときの影響が大きい。全リポジトリに広げるのは、リポジトリごとの allowlist を持てるようになったら再検討する。
- 承認は要求しない。個人リポジトリではレビュー承認なしでマージできる前提にし、承認が必要で `--admin` が要るリポジトリは止まる条件に当てる。
- grill は終了条件が 1 文で書ける小さな作業なら質問 0〜1 回に省く。
- 止まったときは herdr 通知と `PushNotification` で知らせる。通知が多すぎれば herdr 側だけに絞る。
- 並列化は独立した作業単位が 2 つ以上あるときだけ herdr ペインに委譲する。常に並列にすると worktree が競合し、advisor の呼び出しも増える。
- `advisor()` は 1 タスクあたり約 5 回を目安にし、超えたら行き詰まりとして止める。
- PR 本文は日本語で、`visual-pr` の型と Mermaid を使う。
