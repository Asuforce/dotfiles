# create-repo

カレントディレクトリを新規の private GitHub リポジトリとして公開するまでを一続きで行う。

未初期化のディレクトリからでも、ローカルで既にコミットを積んだリポジトリからでも同じ手順で使える。既存の履歴とブランチ名は変更しない。

## Phase 1: 前提の確認

作成に進める状態かを最初に判定する。次の 3 つを実行し、出力と成否から状態を読み取る。

```bash
# 空行 = リポジトリのルート / パス出力 = サブディレクトリ / エラー = 未初期化
git rev-parse --show-prefix
# 成功 = 既にリモートあり / エラー = リモートなし
git remote get-url origin
# 作成するリポジトリ名。空白を含む場合があるため常に引用符で扱う
basename "$PWD"
```

止まる条件。当てはまる場合は理由を報告し、以降を実行しない。

- **サブディレクトリのパスが出力された** — 既存リポジトリの中にいる。`gh repo create --source=.` は親リポジトリを対象にしてしまうため、意図したディレクトリに移動するようユーザーに促す。
- **`origin` の URL が出力された** — 既にリモートに接続済みなので、新規作成の対象ではない。

進め方。

- **未初期化**（`git rev-parse` がエラー）— Phase 2 の初期化から進める。
- **リポジトリのルート**（空行が出力）— 初期化は飛ばし、Phase 2 のコミット確認から進める。

## Phase 2: ローカルリポジトリの準備

未初期化の場合のみ、デフォルトブランチを `main` として初期化する。既存リポジトリでは実行しない（現在のブランチ名をそのまま使う）。

```bash
git init -b main
```

コミットが 1 つも無い場合は初回コミットを作成する。

```bash
# 成功 = コミットあり / エラー = コミットなし
git rev-parse HEAD
# 出力あり = コミット対象あり
git status --porcelain
```

- コミットなし、かつコミット対象あり: 全ファイルをコミットする。

  ```bash
  git add -A
  git commit -m "first commit"
  ```

- コミットなし、かつコミット対象なし: 空のディレクトリなので「コミットするファイルがありません」と報告して終了する。
- コミットあり: 履歴には手を付けない。未コミットの変更が残っている場合もそのまま残し、プッシュ対象に含まれないことを最後に伝える。

## Phase 3: 説明文の材料確認

リポジトリ説明文の材料として、コミット内容を確認する。

```bash
git log --oneline -5
git show --stat HEAD
```

初回コミットのみの場合はその内容から、既存の履歴がある場合は README やルートのファイル構成も踏まえて、リポジトリの説明文を一文で組み立てる。

## Phase 4: 新規リポジトリの作成

private リポジトリを作成し、`origin` として追加する。リポジトリ名は Phase 1 で確認したディレクトリ名を使う。

```bash
gh repo create "$(basename "$PWD")" --private --source=. --description="<Phase 3 で組み立てた説明文>"
```

同名のリポジトリが既にアカウント上に存在する場合は `gh` がエラーを返す。この時点でリモートには何も作られていないため、別名で作り直すかをユーザーに確認する。

## Phase 5: プッシュとブラウザ確認

現在のブランチをプッシュして上流に設定し、作成したリポジトリをブラウザで開く。

```bash
git push -u origin "$(git branch --show-current)"
gh repo view --web
```
